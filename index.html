2. 你的專屬學習方式

這套方法完全不靠固定週數。每一門課只有「通關條件」。

能力解鎖制

一天學會就往下走；卡住就重複真實回合。時間不是進度，能否自然使用才是進度。

先做，再命名

先拿真實問題打一輪，再補框架名稱。避免先背理論造成假理解。

跨專案遷移

同一 Habit 至少在兩種不同領域自然出現，才算真正會。

AI 不准第一個思考

你一定先交自己的版本；AI 只負責攻擊、追問、產生替代模型與扮演 stakeholder。

弱項用回合數，不用週數

強項 1–2 回合確認；中等能力 3–5 回合；主修能力 5–8+ 個不同情境，直到自動啟動。

每次都留下決策證據

保留原始答案、被推翻的地方、最後決定與 revisit trigger，這些同時是轉職作品集素材。

固定訓練迴圈

真實問題→先自己解→套本課 Habit→自己反駁→AI Red Team→真實行動→回顧是否自動觸發
你最適合的學習鏈：
Concrete → Collision → Abstraction → Transfer
先碰真問題 → 舊模型失效 → 抽出原則 → 換領域再用。

4. 詳細課程

點開每一課即可看練習、AI 用法與通關條件。

Course 0｜Baseline：保存你原本的思考必修 · 短

目的

先留下原始決策紀錄，未來才能看出 Habit 是否真的改變了你。

練習

  • 我最後做了什麼決定？
  • 我相信哪些事情是真的？
  • 哪些有證據？哪些只是推論？
  • 我排除過哪些方案？為什麼？
  • 哪個假設如果錯，整個決定會翻盤？
通關：完成 1 份不美化、不用 AI 修正的原始決策紀錄。
Course 1｜Evidence vs Inference必修 · 中

核心問題

我看到的，還是我推論的？

固定拆法

Observation → Interpretation → Assumption → Decision

Boss Fight

從一個正在準備做的功能或決策裡，找出至少 3 個「被你寫成事實、其實只是 inference」的句子。

通關：在真實工作中，不靠 checklist，主動抓到自己至少一次把 inference 當 fact。
Course 2｜Competing Hypotheses主修 · 長

核心問題

還有哪兩個完全不同的解釋？

  1. 寫出主假設。
  2. 至少建立 3 個 competing hypotheses。
  3. 不要問「還能拿什麼資料」，改問「哪份資料能最大幅度區分這些假設」。
  4. 找出最可能改變決策的 evidence。

適合素材

POS 的「太晚知道異常」最適合；醫療的「病人不回應」其次。

通關：開始做 solution 前，會主動列出至少 3 個會導致不同解法的 competing hypotheses。
Course 3｜Explicit Falsification：事前定義自己怎麼錯最高優先 · 最長

核心問題

看到什麼，我會承認自己錯？

CALC//QUEST 已證明你很會用真實結果推翻原判斷；現在要把這能力往前移。

固定格式

如果看到 X → 提高信心。
如果看到 Y → 降低信心。
如果看到 Z → 停止 / pivot。

強制規則

任何 MVP、訪談、功能實驗、架構改動，都先寫 kill criteria，再動手。

通關：至少在 3 個真實專案決策裡，事前寫出 falsification condition，且其中至少一次真的依它改變決策。
Course 4｜Pre-commit Reframing：在鎖定前換模型精準補強 · 中

核心問題

是不是第一個模型太合理，所以我停止換角度了？

只要你已經很快覺得「根因就是 X」，就強制再做兩個 problem representation。

例：POS

  • 怎麼讓老闆知道異常？
  • 怎麼讓異常被處理？
  • 怎麼讓老闆根本不需要知道？
可跳條件：如果你在兩個不同專案裡都能自然換模型，不需大量練。
通關：第一個模型成立時，仍會自然補問：「如果這個模型是錯的，另一種問題描述會是什麼？」
Course 5｜Complex Systems最高優先 · 最長

核心問題

我動這裡後，誰會改變行為？然後呢？

  • 有哪些 actor？
  • 誰的 KPI、誘因、工作量會改變？
  • 哪裡有 delay？
  • 哪裡會出 workaround？
  • 短期成功是否可能造成長期失敗？
  • 哪個 feedback loop 會把效果放大或抵消？
  • 局部最佳化會不會傷害整體？

醫療 Boss Fight

對一個 intervention 畫出至少 2 feedback loops、2 delays、2 unintended consequences、2 behavioral adaptations。

通關：看到「加功能就能解決」時，會自動往後推至少三層，而且會想到人類會適應系統。
Course 6｜Decision Architecture最高優先 · 最長

核心問題

我到底在最佳化什麼？

  • Options：真正不同的選項。
  • Value：成功價值。
  • Evidence / Confidence：有多確定。
  • Cost：時間、技術、組織成本。
  • Reversibility：錯了能不能回頭。
  • Stakeholder trade-off：誰得利、誰承擔成本。
  • Decision rule：什麼條件下選 A，而不是 B。
  • Revisit trigger：什麼情況要翻案。

不是教你「做取捨」；你已經會。這一課是把腦內直覺外顯成別人可以 challenge 的決策。

通關：把一個模糊分析寫成 1-page decision memo，而且別人可以指出你哪個 criteria 或 evidence 有問題。
Course 7｜Uncertainty & Reversibility主修 · 中長

核心問題

哪個未知最值得花力氣降低？這個決策錯了能不能回頭？

  • 高影響 + 低信心：優先取資訊。
  • 高影響 + 高信心：直接決策。
  • 低影響 + 可逆：快速做。
  • 不可逆：先確認最致命未知。

轉職練習

技術 PM / 內部創業 PM vs Solution Architect，不做「哪個比較好」，而是找出高影響、低信心的未知數，再設計情報任務。

通關：會根據可逆性與資訊價值決定「分析多少」，不再所有決策都同樣用力。
Course 8｜Pre-mortem & Pre-commitment新增主修 · 長

核心問題

如果這個決策最後失敗，最可能是什麼把我打敗？

  1. 假設這個決策已經失敗。
  2. 列出最可能的 3–5 個失敗原因。
  3. 挑出現在就能測的 failure signal。
  4. 預先寫明中止、轉向、降級的條件。

適合素材

POS 是否值得進入 MVP；醫療某功能是否值得深度整合；轉職方向是否需要追加投入。

通關：執行前就能寫出最可能的失敗路徑，而且至少一次因預警訊號提早改變方案。
Course 9｜Effective Communication附著訓練 · 中

核心問題

我是不是把 why 壓縮掉了？

  1. Problem
  2. Evidence
  3. Alternatives
  4. Decision
  5. Why
  6. Risk / Revisit Trigger

每次 Boss Fight 都做

  • 1-page decision memo
  • 3-minute verbal summary
  • 60-second executive version
通關：別人能在短時間內看出 evidence → reasoning → decision，而不是只聽到 solution。
Course 10｜Integration & Transfer畢業考 · 最長

規則

挑一個新的真實問題，第一輪完全不看框架。

完成後才回頭檢查

  • 有沒有分 evidence / inference？
  • 有沒有 competing hypotheses？
  • 第一個模型成立後有沒有再換 representation？
  • 有沒有事前 falsification？
  • 有沒有想到 feedback / delay / behavior adaptation？
  • 有沒有明確 decision rule？
  • 有沒有 pre-mortem 與 revisit trigger？
  • 能不能 3 分鐘說清楚？
通關：大部分 Habit 在沒有提示下自己出現，而且能跨兩種以上領域使用。

5. 三個現有專案怎麼分工

醫療病人追蹤系統

主練：Complex Systems、Decision Architecture、Stakeholder trade-off、Evidence。

角色多、流程長、風險高，最適合把你從「工程可做」拉到「系統是否真的變好」。

POS 營運提醒 MVP

主練：Competing Hypotheses、Falsification、Pre-mortem、Product Decision。

需求、市場與願付價值都不確定，是訓練 kill criteria 的最佳場域。

互動動畫 / CALC//QUEST 類創作

主練：Transfer、Reframing、Creative Models、Scope Decision。

用來確認你的創意不是只在熟悉工程問題裡有效。

6. 跨 AI 使用規則

把這份 HTML 丟給任何 AI 時，先要求它遵守以下規則。

總教練提示詞

你現在是我的 Minerva-style 思考教練。 規則： 1. 不要先替我解題。 2. 我一定先交自己的答案。 3. 你的主要工作是追問、找推論跳躍、找替代模型、要求證據、扮演 stakeholder。 4. 不要因為我的答案「看起來合理」就接受。 5. 如果我已經在做高品質最佳化，請先檢查我是不是鎖錯 problem model。 6. 每次都要檢查：Evidence、Competing Hypotheses、Falsification、Systems、Decision Rule、Revisit Trigger。 7. 如果我已經自然做到某項能力，請不要重教，直接提高難度或讓我跨領域遷移。 8. 除非我明確要求，否則不要給完整標準答案。

Red Team

只做攻擊，不給完整解法： - 哪裡把 inference 當 fact？ - 哪個假設沒有證據？ - 哪三個 competing explanations 也成立？ - 哪份 evidence 最可能改變決策？ - 看到什麼結果，我應該承認自己錯？

Systems Challenger

把我的方案視為會改變人類行為的 intervention。 請追問： - 哪些 actor 會改變行為？ - 哪裡有 delay？ - 哪裡會形成 feedback loop？ - 有什麼 workaround？ - 短期成功是否可能導致長期失敗？ - 哪個二階效果最值得先監控？

Decision Coach

不要替我決策。 只檢查： Options / Value / Evidence / Confidence / Cost / Reversibility / Stakeholder trade-off / Decision rule / Revisit trigger / Kill criteria。 缺什麼就用問題逼我補齊。

7. 最後要留下的作品證據

醫療 Case

模糊方向 → 系統圖 → competing hypotheses → intervention → metrics → decision memo。

POS Case

市場假設 → problem reframing → kill criteria → experiment → MVP / no-MVP decision。

創作 Case

原始概念 → scope 取捨 → 玩家 / 使用結果 → 被推翻假設 → 新模型 → 架構與產品判斷。

每個 Case 固定保存

  1. 原始模糊問題
  2. 第一直覺
  3. 競爭假設
  4. 哪個 Habit 改變了理解
  5. 最後決策與理由
  6. Kill criteria / Revisit trigger
  7. 結果是否推翻原判斷
  8. 下一次會提早看見什麼

8. 畢業標準

Level 1

知道概念，看到例子能理解。

Level 2

有 checklist 時能使用。

Level 3

真實專案中，不提醒也會使用。

Level 4

換領域仍會使用，而且會組合多個 Habit。

Level 5

知道何時不該用、能批判工具本身，也能教別人。

你的目標：
不要求全部 Level 5。先讓主修能力至少達 Level 3；其中 Falsification、Decision Architecture、Complex Systems 至少有一部分進到 Level 4。

最後只需要背 7 句話

  1. 我看到的，還是我推論的？
  2. 還有什麼完全不同的解釋？
  3. 第一個模型是不是太快鎖定了？
  4. 看到什麼，我會承認自己錯？
  5. 我動這裡後，誰會改變行為？然後呢？
  6. 我到底在最佳化什麼？
  7. 如果這個決策最後失敗，現在最早會出現什麼訊號？
